Snapshot Package Layout

One snapshot is the reproduction unit. It bundles what is small and specific to the study, and pins what is large and shared across studies.

The package

wbm_storage_v2.0.0 @ v2 the reproduction unit — immutable
├── model/ utilities/ bundled — ~1 MB, study-specific, sha256 recorded
├── wbm_init/ bundled — run configuration
├── gdal_test_files/ bundled — GDAL fixtures the model probes at startup
├── metadata.json identity + pins
│ ├── $schema snapshot-spec 1.0.0 → spec repository · semver
│ ├── container wbm-v2-lite@sha256:9f2c… → image registry · digest
│ ├── modelInput 7d4e9a… → model input store · id
│ └── modelCode sha256:3ab7… (WBM 2.0.0) ↑ hash of the bundled code above
└── wbm_output/ published results — excluded from identity

Three fields in metadata.json point outward; one points inward. That single file is what makes the snapshot a reproduction unit — it is the only place from which every other versioned artifact can be named.

How it assembles at run time

The tree above shows what is on disk. The graph below shows what actually moves: four inputs reach the run, and everything the run produces lands in a separate writable scratch directory. The snapshot is mounted read-only, so no output ever goes back into it — including the output the snapshot already carries, which is never mounted and never rewritten.

What you deploy

Almost nothing new. The openghm namespace on Anvil's Composable Subsystem already runs the backend, frontend, MongoDB, and ingress-nginx with cert-manager. You add two workloads to it — a container registry (zot) and a static host for the schema files — and reuse the certificate issuer that is already there. zot stores its blobs directly in Anvil S3, so there is no new in-cluster storage to size or manage.

registry

zot + ORAS

Single-binary OCI registry, Helm chart, blobs stored directly in Anvil S3. apptainer push oras:// stores the SIF as one blob, so a pull returns the bytes that were verified. Search zot registry helm chart.

schema registry

JSON Schema on a static host

Versioned files in git, published at immutable URLs, validated with check-jsonschema and code-generated with datamodel-code-generator. Apicurio Registry is the heavier option if the schema ever needs an API or a UI.

stores

Anvil S3

Snapshots and raw data sit in the existing Anvil openghm bucket under immutable prefixes. No DOI minting for now — each version is just a serial number, published once and never overwritten.

Where the pinned artifacts live

contract · semver

Spec repository

JSON Schema in git, published at versioned URLs. Covers both the folder layout and the metadata fields as one contract, so there is no compatibility matrix between them.

content · digest

Image registry

zot on Anvil's Composable Subsystem as the origin, with prebuilt SIFs mirrored to plain Anvil S3 for credential-free HPC reads. Pinned by digest, never by tag — a rebuilt tag is not the same image.

dataset · serial

Shared data store

Anvil S3 under immutable prefixes, described with HydroShare's CompositeResource vocabulary (borrowed, not deployed). Shared by many snapshots, so it is referenced rather than copied into each one.

What goes in, what stays out

ItemStoredWhy
Model code + utilities inside ~1 MB, so deduplication saves nothing. Its _Inline directory holds perl-5.30 objects tied to the container, so it is not cleanly shareable — and the runtime already mounts it from the snapshot.
Run configuration inside Small and unique to this snapshot.
Container image outside ~350 MB and shared across snapshots. Bundled physically only at publication, so a deposited archive survives the registry.
Raw input data outside TB-scale and shared across snapshots. Copying it per snapshot is not viable.
spool cache outside Regenerable, and decided by the model input, the network and the run's settings, not by the snapshot. Kept once per variant and shared by every run and snapshot that needs it.
