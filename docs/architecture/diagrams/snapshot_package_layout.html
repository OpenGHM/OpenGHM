Snapshot Package Layout

One snapshot is the reproduction unit. It bundles what is small and specific to the study, and pins what is large and shared across studies.

The package

wbm_storage_v2.0.0 @ v2 the reproduction unit — immutable
├── model/ utilities/ bundled — a few MB, study-specific, pinned by tree hash
├── wbm_init/ bundled — run configuration
├── gdal_test_files/ bundled — GDAL fixtures the model probes at startup
├── metadata.json identity + pins
│ ├── $schema snapshot-spec 1.0.0 → snapshot spec · semver
│ ├── container wbm-v2-lite@sha256:9f2c… → image registry · digest
│ ├── modelInput 7d4e9a… → model input store · id
│ └── modelCode wbm 23.9.0 · treeHash 664c29… ↑ tree hash of the bundled code above
├── SHA256SUMS integrity manifest — everything except wbm_output/
├── WBM_run_state/ optional — the published run's resume state; a fetch skips it
└── wbm_output/ published results — excluded from identity

Three fields in metadata.json point outward; one points inward. That single file is what makes the snapshot a reproduction unit — it is the only place from which every other versioned artifact can be named.

How it assembles at run time

The tree above shows what is on disk. The graph below shows what actually moves: four inputs reach the run, and everything the run produces lands in a separate writable scratch directory. The snapshot is mounted read-only, so no output ever goes back into it — including the output the snapshot already carries, which is never mounted and never rewritten.

What runs where

The deployment is small. Anvil's Composable Subsystem runs ingress-nginx with cert-manager and two namespaces. openghm-dev holds the gateway — frontend, backend and MongoDB — at dev.openghm.org. openghm is prod: zot, the SIF registry, an nginx proxy that serves the schema files out of S3, and a landing page, with the gateway's manifests present at no replicas. zot stores its blobs directly in Anvil S3 and the proxy reads from it, so neither has state of its own; MongoDB is the one workload with a volume. There is no CI service and the repositories have no remote: a maintainer's workstation applies the manifests and pushes the images, and everything that writes to S3 runs on Anvil, with s3cmd.

registry

zot + ORAS

Single-binary OCI registry, a plain Kubernetes manifest, blobs stored directly in Anvil S3. oras push stores the SIF as one blob, so a pull returns the bytes that were verified.

schemas

JSON Schema on a proxy

Versioned files in schemas/, copied to Anvil S3 and served by an nginx proxy at schemas.openghm.org. The backend models and frontend types are generated from them by just codegen.

stores

Anvil S3

Snapshots, model inputs, spools, code and images sit in the Anvil openghm bucket, one prefix each. No DOI minting for now — a snapshot or model input gets a minted id at publish, and that id is never reused.

Where the pinned artifacts live

contract · semver

Snapshot spec

JSON Schema and a path list in schemas/, published at versioned URLs. Covers both the folder layout and the metadata fields as one contract, so there is no compatibility matrix between them.

content · digest

Image registry

zot on Anvil's Composable Subsystem as the origin, with prebuilt SIFs mirrored to plain Anvil S3 for credential-free HPC reads. Pinned by digest, never by tag — a rebuilt tag is not the same image.

dataset · minted id

Model input store

Anvil S3 under model-inputs/<id>/, one prefix per published model input. Shared by many snapshots, so it is referenced rather than copied into each one.

What goes in, what stays out

ItemStoredWhy
Model code + utilities inside A few MB (4.5 MB for Global's model/), so deduplication saves nothing. Its _Inline directory holds perl-5.30 objects tied to the container, so it is not cleanly shareable — and the runtime already mounts it from the snapshot.
Run configuration inside Small and unique to this snapshot.
Container image outside About 330 MB and shared across snapshots. Kept in zot and in the S3 mirror, and pinned by digest; a snapshot stores no copy.
Raw input data outside 49 GB for Global's model input, shared across snapshots. Copying it per snapshot is not viable.
spool cache outside Regenerable, and decided by the model input, the network and the run's settings, not by the snapshot. Kept once per variant and shared by every run and snapshot that needs it.
